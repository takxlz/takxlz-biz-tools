# agents

Claude Code のサブエージェント定義（`*.md`）置き場。ここは実行するツールではなく、
Claude Code に読み込ませる資産のディレクトリ。

収録しているのは**ループエンジニアリング**（1回のプロンプトを磨くのではなく、エージェントを
回し続ける仕組みの側を設計するやり方）のためのスイート。ループの局面ごとに1体ずつ、
役割が重ならないように分けている。

## 収録エージェント

| ファイル                             | 局面     | 役割                                                             |
| ------------------------------------ | -------- | ---------------------------------------------------------------- |
| [loop-designer.md](loop-designer.md) | 開始前   | 曖昧なゴールを、検証可能な完了条件・停止条件・記録先まで落とした仕様にする |
| [loop-scout.md](loop-scout.md)       | 各周の頭 | 次に回す作業を1件だけ根拠付きで選ぶ。無ければ「作業なし」で止める |
| [loop-verifier.md](loop-verifier.md) | 各周の尻 | 1周を独立検証し `continue` / `done` / `escalate` を判定する       |
| [loop-doctor.md](loop-doctor.md)     | 数周ごと | 周の並びを診て、空回り・骨抜き・膨張を検出し継続可否を勧告する    |

いずれも **read-only**（`Bash, Read, Grep, Glob`。Edit / Write を持たない）。実装するのは
呼び出し側のメインエージェントで、この4体は「決める・探す・確かめる・診る」だけを担う。

## 組み合わせ方

```
[開始前]  loop-designer ──→ LOOP.md（契約）
             │
             ▼
[各周]    loop-scout ──→ 実装（メインエージェント） ──→ loop-verifier ──→ loop-log.md に1行追記
             ▲                                              │
             └──────────────── continue ────────────────────┤
                                                            ├─ done ──→ 終了
                                                            └─ escalate ─┐
[数周ごと / escalate 時]  loop-doctor ──→ 続行 / 仕様修正 / 停止 / 人間へ ←┘
```

`/loop` と組み合わせるときのプロンプト雛形:

```
/loop 15m LOOP.md の完了条件を1つずつ潰す。
各周: (1) loop-scout で次の1件を決める。「作業なし」なら loop を止める。
      (2) 実装する。(3) loop-verifier で検証する。
      (4) 判定の「進捗ログ」行を loop-log.md に追記する。
      done なら loop を止め、escalate なら loop-doctor を呼んでから止める。
3周ごとに loop-doctor を呼び、「停止」「人間に引き渡し」なら loop を止めて報告する。
```

### 外部記憶（ログ）の約束

ループが前の周を覚えていないと、同じ失敗を延々と繰り返す。エージェント側ではなく
**ファイル**に持たせる。

- `LOOP.md` … 契約（ゴール・完了条件・停止条件・上限・禁止事項）。loop-designer が書式を出す。
- `loop-log.md` … 追記のみの進捗ログ。1行形式は `<日時> | <周> | <判定> | <打った一手> | <結果>`。
  loop-verifier が出力末尾に出す「進捗ログ」行をそのまま足していく。

loop-scout はこの2つを読んで未達を探し、loop-doctor はこの2つと git 履歴を突き合わせて診断する。
つまりログを書かないとスイートの後半2体が機能しない。

## インストール

Claude Code は `~/.claude/agents/`（全プロジェクト共通）と `<repo>/.claude/agents/`（プロジェクト限定）
を読む。このリポジトリはあくまで保管場所なので、使う側からリンクするか複製する。

```sh
# 全プロジェクトで使う
for f in "$PWD"/agents/loop-*.md; do ln -s "$f" ~/.claude/agents/; done

# 特定プロジェクトだけで使う
cp agents/loop-*.md /path/to/project/.claude/agents/
```

リンクにしておくとここを直せば全プロジェクトに反映される。複製した場合は追従しない。

## 設計メモ（非自明な判断）

- **なぜ全部 read-only か** … 検証者や診断役が修正までできると「自分で直して自分で合格にする」構図に
  戻り、独立した目という存在理由が消える。テストの緩和・skip・完了条件の書き換えも、提案までに留めさせている
  （緑にするだけならいくらでもできてしまうため）。
- **なぜ verifier と doctor を分けたか** … 見る単位が違う。verifier は1周の中身、doctor は周の並び。
  1周ずつは正しく見えるのに全体では進んでいない、という失敗は1周の中からは見えない。
  同じエージェントに両方やらせると、直近の1周に引きずられて傾向を見落とす。
- **なぜ scout が「作業なし」を返せるようにしたか** … ループの停止条件は「完了」だけではない。
  作業の発見役が候補をひねり出す性質を持つと、ループは永遠に終わらない。
- **なぜ designer を回す前に置くか** … 空回りの原因はたいてい実行時ではなく設計時に仕込まれている
  （完了条件が検証不能・停止条件が無い・1周が大きすぎる）。検証手段が無いリポジトリでは、
  「まず検証手段を作る」ことを最初のループにするよう提案させている。
- **判定は3値** … `continue` / `done` に加えて `escalate`。合否2値だと、進まないループが
  `continue` を出し続けて止まらない。
- **`未検証` を合格に寄せない** … 確かめられなかった項目は不合格でも合格でもなく未検証として残す。
- **出力は短く固定形式** … 毎周呼ぶのでトークンが積み上がる。実行ログの引用は要点のみに制限し、
  次の周にそのまま渡せる形にしてある。
- **モデルは未指定**（呼び出し元を継承）。verifier / doctor の精度を上げたい、scout を安く回したい
  といった調整は各 frontmatter に `model:` を足す。
